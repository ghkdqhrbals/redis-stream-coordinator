# Redis Stream Coordinator 0.3.0 Release

Release date: 2026-06-15

This minor release moves producer routing to stream scope, removes producer-side consumer group configuration, adds null partition-key load distribution, and updates the Grafana/admin operator surfaces.

## Breaking and Migration Notes

Producer routing is now stream-scoped:

* New endpoint: `GET /coord/v1/streams/{streamPrefix}/producer-routing`
* Removed endpoint: `GET /coord/v1/streams/{streamPrefix}/groups/{consumerGroup}/producer-routing`
* `StreamProducer` and `ProducerRoutingProperties.producer(...)` no longer accept `consumerGroupName`.
* Consumers still use `consumerGroupName` for heartbeat, assignment, lag, pending, and Redis Stream consumer group semantics.

Producer configuration after migration:

```kotlin
@Bean("ordersStreamProducer")
fun ordersStreamProducer(
    coordinatorClient: CoordinatorClient,
    redisConnectionFactory: RedisConnectionFactory,
): StreamProducer =
    StreamProducer(
        streamPrefix = "orders",
        client = coordinatorClient,
        redisConnectionFactory = redisConnectionFactory,
        routingRefreshInterval = Duration.ofSeconds(30),
        xadd = RedisStreamXAddConfiguration(maxLen = 10_000_000),
    )
```

## Producer Routing

Physical shard topology is authoritative at stream level. Producer routing metadata now contains `streamPrefix`, `metadataVersion`, `shardCount`, `streamKeyPattern`, and concrete shard keys without requiring a consumer group.

`partitionKey` is nullable:

* Non-null partition keys use deterministic Murmur3 routing and preserve per-key shard affinity for a fixed shard count.
* `partitionKey = null` uses producer-local load distribution across active shards. It is only for workloads that do not require per-key ordering or affinity.

## Grafana and Admin Console

Grafana dashboards now include:

* an Admin Console link,
* a Stream Detail panel that queries stream-level producer routing,
* import dashboard links that use the configured `COORDINATOR_API_URL`,
* the existing stream messages, sharding overview, rate, lag, pending, member, and ownership panels.

The built-in admin console now signs in through `/coord/v1/auth/login`, stores a bearer token, shows token expiry, and presents stream-level shard create/scale controls. Scale target `0` remains valid for drain-and-remove workflows.

## Maven Central Usage

```kotlin
implementation("io.github.ghkdqhrbals:redisstream-spring-boot-starter:0.3.0")
```

Use `redisstream-core` directly only when implementing low-level protocol integrations:

```kotlin
implementation("io.github.ghkdqhrbals:redisstream-core:0.3.0")
```
