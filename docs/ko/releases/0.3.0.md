## Breaking / Migration Notes

Producer routing은 이제 stream-scoped이다.

* 신규 endpoint: `GET /coord/v1/streams/{streamPrefix}/producer-routing`
* 제거된 endpoint: `GET /coord/v1/streams/{streamPrefix}/groups/{consumerGroup}/producer-routing`
* `StreamProducer`와 `ProducerRoutingProperties.producer(...)`는 더 이상 `consumerGroupName`을 받지 않는다.
* Consumer는 heartbeat, assignment, lag, pending, Redis Stream consumer group semantics를 위해 계속 `consumerGroupName`을 사용한다.

마이그레이션 후 producer 설정:

```kotlin
@Bean("ordersStreamProducer")
fun ordersStreamProducer(
    coordinatorClient: CoordinatorClient,
    redisConnectionFactory: RedisConnectionFactory,
): StreamProducer =
    StreamProducer(
        streamPrefix = "orders",
        client = coordinatorClient,
        redisConnectionFactory = redisConnectionFactory,
        routingRefreshInterval = Duration.ofSeconds(30),
        xadd = RedisStreamXAddConfiguration(maxLen = 10_000_000),
    )
```

## Producer Routing

물리 shard topology는 stream level이 source of truth다. Producer routing metadata는 consumer group 없이 `streamPrefix`, `metadataVersion`, `shardCount`, `streamKeyPattern`, concrete shard keys를 제공한다.

`partitionKey`는 nullable이다.

* Non-null partition key는 deterministic Murmur3 routing을 사용하며, 같은 shard count 안에서 per-key shard affinity를 보장한다.
* `partitionKey = null`은 active shard 전체에 producer-local load distribution을 수행한다. Per-key ordering이나 affinity가 필요 없는 workload에만 사용해야 한다.

## Grafana / Admin Console

Grafana dashboard 변경:

* Admin Console 링크 추가
* Stream Detail dashboard에서 stream-level producer routing 직접 조회
* Import dashboard는 설정된 `COORDINATOR_API_URL`로 admin link와 coordinator API를 구성
* 기존 stream messages, sharding overview, rate, lag, pending, member, ownership panel 유지

내장 admin console은 `/coord/v1/auth/login`으로 로그인하고 bearer token을 저장한다. Token 만료 시간을 표시하며 stream-level shard create/scale control을 제공한다. Target shard `0`은 drain-and-remove workflow를 위해 계속 유효하다.
